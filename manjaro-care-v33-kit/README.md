# حزمة تنفيذ خطة `manjaro-care` v3.3 — دليل التشغيل على جهازك

**تاريخ الإعداد:** 10 نوفمبر 2026
**طبيعة الحزمة:** تحضيرية فقط — استخراج حرفي (byte-faithful) للسكربتات السبعة المضمّنة في وثيقة الخطة v3.3 (9 نوفمبر 2026، بتعديلها المعتمد 10 نوفمبر 2026) إلى ملفات جاهزة، مع دليل تشغيل وقالب سجل.
**إفصاح حاكم:** مُعدّ هذه الحزمة لم ينفّذ أي أمر يمس GitHub أو الشبكة أو أي توكن — لا قياسات حية ولا استعلامات ولا مصادقة (القاعدة 12). لا يحوي أي توكن أو سر. السكربتات الست حرفية دون تعديل حرف واحد؛ السكربت السابع `mc-t32-merge.sh` عُدّل **بقرار معتمد من المالك (10 نوفمبر 2026)**: إضافة حارس ما قبل الدمج — مدخل `OLD_MAIN_SHA` وقراءة حية ومقارنة بـmain قبل أمر الدمج (التفصيل في §13) — وكتلته في الوثيقة المصدر عُدّلت به ذات الطريقة حرفيًا، وأُعيد توليد البصمات.
**نتيجة التحقق المحلي:** فحص بنية Bash (`bash -n`) ناجح للسبعة · 42 فحصًا نصيًا على نقاط التدقيق الـ11 (6 ملاحظات + 5 شروط بوابات) وفحوص شاملة إضافية — **42/42 PASS، صفر انحراف** · مطابقة حرفية 7/7 بين كتل الوثيقة وملفات الحزمة · اختبار وظيفي معزول للسكربت المعدّل **5/5 سيناريوهات** (§13).

## 2) القاعدة الحاكمة قبل أي خطوة

- **كل ما يمس GitHub أو الشبكة أو أي توكن يُنفَّذ على جهازك حصرًا.** المساعدون يعدّون الأوامر ويفسّرون المخرجات التي تلصقها ويحرّرون النص؛ لا يملكون توكنًا ولا ينفّذون أمرًا يمس GitHub (القاعدة 12).
- **التوكن يعيش لحظة الاستعمال فقط** في `GH_TOKEN` داخل الجلسة: يُدخَل بـ`read -rs` دون صدى، ويُحذف بـ`unset` فور انتهاء الخطوة. **لا تلصق توكنًا في أي محادثة أبدًا — تلصق المخرجات فقط.**
- **لا استعمال للتوكنين المسرَّبين القديمين بأي شكل** — لا حتى للتحقق من إبطالهما (القاعدة 10).

## 3) قبل أي تشغيل: G1 ثم G2

### بوابة G1 — تُنجزها أنت من واجهة المتصفح
1. أصل إلى صفحات إدارة التوكنات في إعدادات GitHub مباشرة.
2. ألغِ (Revoke/Delete) التوكنين المسرَّبين **دون أي طلب API بالتوكن القديم**.
3. دوِّر الرمزين `repo-sync-toolkit` و`medical-translation-bot` من مواضع تخزينهما الفعلية إن لم يكتسب الدوران.
4. أرسل لي تأكيدك النصي (مثال الصيغة في القالب §أ) — **لا يبدأ أي عمل، حتى القرائي، قبله.**

### بوابة G2 — اعتمادك النصي للوثيقة
الاعتماد **يفعّل المراحل القرائية T0–T2 فقط**؛ كل وحدة كتابة (T3.1 ثم T3.2) تأتيك بطلب موافقة مستقل بجدولها الكامل عند بلوغها.

### نقاط القرار السبع (القسم 9 من الوثيقة) — ملخص
1. G1 (أعلاه). 2. مراجعة سجل التغييرات (القسم 0) اعتمادًا أو تعديلًا. 3. اعتماد القالب الثلاثي أساسًا (⇒ G4). 4. النسخ الاحتياطي على جهازك فقط (⇒ G-T1)؛ الخيار ب معلّق ولا يُنفَّذ. 5. إصدار توكن القراءة وتوثيق إعداداته (⇒ G3-R). 6. كلمة الاعتماد على الخطة (⇒ G2). 7. تعبئة جدول المدخلات (§9 أدناه) فيما يخص ما قبل التنفيذ.

حتى اكتمالها: لا كتابة، لا دمج، لا إغلاق، لا حذف، لا توكن كتابة، ولا استعمال لأي توكن قديم — لا شيء.

### إصدار توكن القراءة G3-R (عند بلوغه)
Selected repositories = `manjaro-care` فقط · Metadata: R · Contents: R · Pull requests: R · Issues: R · ≤ 7 أيام. **دوّن إعدادات الإنشاء لحظة التصدير — هي الدليل الأساسي لضيق النطاق.** ثم اختبره تشغيليًا على جهازك (فحوص الوثيقة 3.3) والصق المخرجات لي:

```bash
read -rsp "توكن G3-R (لا يظهر على الشاشة): " GH_TOKEN; echo; export GH_TOKEN
gh api repos/DrAbdulmalek/manjaro-care --jq .full_name
gh api repos/DrAbdulmalek/manjaro-care/pulls --jq length
gh api repos/DrAbdulmalek/manjaro-care/issues --jq length
gh api repos/DrAbdulmalek/manjaro-care/contents/README.md --jq .sha
gh api repos/DrAbdulmalek/manjaro-doctor
unset GH_TOKEN
```

**تحذير منهجي:** نجاح هذه القراءات يثبت أن التوكن يعمل فقط؛ نجاح قراءة مستودع عام آخر (`manjaro-doctor`) لا يثبت تجاوز النطاق، ولا `403` دليلًا قاطعًا على الضيق. الحكم بالإعدادات الموثقة عند الإنشاء. لا اختبارات كتابة قبل T3.

## 4) التسلسل الحاكم (كل سهم إلى كتابة = موافقة مستقلة منفصلة)

```
G1 → G2 → G3-R → T0 → T1 → G-T1 → G4 → عرض T2 → اعتماد T2

   → [توقف عند بابك — قرار التعميم مستقل لاحقًا]
```

## 5) مرحلة T0 — إعادة تحقق حي شاملة (قراءة فقط، على جهازك، والصق المخرجات لي)

أدخل التوكن ثم نفّذ بنود 1–3 (جميعها قراءة على `manjaro-care`):

```bash
read -rsp "توكن G3-R (لا يظهر): " GH_TOKEN; echo; export GH_TOKEN
# البند 1: تفصيل PR #14 وPR #15
gh pr view 14 --repo DrAbdulmalek/manjaro-care --json number,title,state,isDraft,headRefName,baseRefName,headRefOid
gh pr view 15 --repo DrAbdulmalek/manjaro-care --json number,title,state,isDraft,headRefName,baseRefName,headRefOid
# البند 1 تتمة: حساب تخلف #15 عن main — استبدل ما بين علامتي الاقتباس بما ظهر في headRefName لناتج #15 أعلاه
gh api "repos/DrAbdulmalek/manjaro-care/compare/main...ضع-هنا-اسم-فرع-15" --jq '{status, ahead_by, behind_by}'
# البند 2: حالة الدمج المحسوبة لـ#16 و#15
gh pr view 16 --repo DrAbdulmalek/manjaro-care --json number,mergeable,mergeStateStatus,headRefOid
gh pr view 15 --repo DrAbdulmalek/manjaro-care --json number,mergeable,mergeStateStatus
# البند 3: تشغيلات CI على main — خط أساس قبل التغيير
gh run list --repo DrAbdulmalek/manjaro-care --branch main --limit 20
unset GH_TOKEN
```

ثم البنود 4–5 **دون توكن** (مستودعات عامة — حفاظًا على ضيق نطاق G3-R):

```bash
# البند 4: حالة PR #7 في المستودع العام repo-sync-toolkit — توثيق فقط، دمجه خارج التجربة
gh api repos/DrAbdulmalek/repo-sync-toolkit/pulls/7 --jq '{state, merged, merged_at}'
# البند 5: أثر manjaro-doctor في manjaro-care — مقارنة سريعة بلا توكن (نسخة عمل مؤقتة تُحذف فورًا)
git clone --bare --filter=blob:none https://github.com/DrAbdulmalek/manjaro-care.git /tmp/mc-t0-care.git
git -C /tmp/mc-t0-care.git fetch --no-tags https://github.com/DrAbdulmalek/manjaro-doctor.git main:refs/md/doctor
git -C /tmp/mc-t0-care.git merge-base --is-ancestor refs/md/doctor refs/heads/main && echo "doctor سلف لـmain (مدموج)" || echo "ليس سلفًا مباشرًا — الصق لي مخرجات المقارنة"
git -C /tmp/mc-t0-care.git log --oneline -n 5 refs/md/doctor
rm -rf /tmp/mc-t0-care.git
```

ثم البند 7 — إعادة قياس خط الأساس (بروتوكول git، بلا توكن) والبند 6 — توثيق تأكيد إبطال التوكنين في السجل:

```bash
git ls-remote https://github.com/DrAbdulmalek/manjaro-care.git refs/heads/main refs/heads/chore/repo-governance
```

**المخرجات المطلوب لصقها لي:** نواتج البنود 1–5 + SHAs الكاملة من البند 7 + تأكيد الإبطال (نصيًا، من لوحة الإدارة). سأحدّث بعدها جدول خط الأساس وأعد لك «خط أساس قبل التغيير» موثقًا.

## 6) مرحلة T1 — النسخ الاحتياطي المشفّر (على جهازك) ⇒ بوابة G-T1

**تجهيز المفتاح (مرة واحدة، خارج مجلد النسخة):**

```bash
mkdir -p ~/.config/age && age-keygen -o ~/.config/age/mc-backup-key.txt
chmod 600 ~/.config/age/mc-backup-key.txt
```
ثم خزّن نسخة من المفتاح في موقع مستقل تصرّح به (مدير كلمات مرور أو وسيط غير متصل) — هذا موقع `AGE_KEY_BACKUP_LOCATION` الإلزامي، ووجود المفتاح اليوم لا يضمن الاستعادة مستقبلًا؛ اختبر النسخة الاحتياطية دوريًا باستعادة فعلية **منها**.

**فحوص بيئة جهازك (تُسجل للإحاطة — القسم 10.2):**

```bash
df -h /dev/shm /tmp ; findmnt -no FSTYPE -T "$HOME" ; swapon --show
```

**التشغيل** (بعد إدخال G3-R في الجلسة كما في §5، وكل ملفات الحزمة في مجلد واحد):

```bash
bash mc-backup.sh
```

كل البوابات آلية داخله (الأدوات ← التوكن ← المفتاح المحصَّن ← swap ← tmpfs والسعة ← fsck بـpipefail ← بنية JSON ← تشفير مُثبَت قبل حذف الأصل ← الطبقات ①②③④ ← نشر ملفين ← نظافة). عند أي `FAIL` توقف والصق لي السجل كاملًا للتفسير — لا تعِد المحاولة آليًا.

**انسخ إلى سجل التجربة (SC8):** `MAIN_SHA` · `ENC_FILE` · `ENC_SHA256` · `ENC_SIZE_BYTES` + نتيجة كل طبقة ①–④ + فحص النظافة. ثم انقل الأرشيف المشفّر إلى وسيطك الآمن وأبقه، وأكّد لي اكتمال ما سبق نصيًا ⇒ **G-T1** (شرط دخول T2).

## 8) عرض T2 ثم وحدات الكتابة T3.1 / T3.2 (كل وحدة موافقة نصية مستقلة)

**عرض T2:** أرسل لي مخرجات T0 ومخرجات T1 ⇒ أُعد لك جدول القرارات (#16 دمج بعد تحديث الفرع بموافقتين مستقلتين؛ الثمانية #23/#24/#25/#26/#27/#29/#30/#31 لا تُلمس؛ #14/#15 لا تُلمسان؛ Dependabot بعد الدمج يفتح PRs وفق جدوله بلا ضمان) ⇒ اعتمادك النصي للجدول **لا ينفّذ أي وحدة تلقائيًا**.

**T3.1 — تحديث فرع #16:** ترسل لي أولاً القياس الحي الطازج (أمر `git ls-remote` في §5 بند 7) ⇒ أُعد لك جدول G5 بالـSHAs الكاملة (رأس الفرع + رأس main) ⇒ موافقتك النصية المستقلة (G5) ⇒ **عندها فقط** تصدر توكن الكتابة G3-W (Selected repositories = `manjaro-care` فقط · Contents: RW · Pull requests: RW · **لا** Administration · **لا** Workflows · ≤ 72 ساعة) وتوثق إعداداته ⇒ تشغّل:

```bash
read -rsp "توكن G3-W (لا يظهر): " GH_TOKEN; echo; export GH_TOKEN
export APPROVED_HEAD_SHA="الصق هنا SHA رأس الفرع من جدول G5"
export APPROVED_BASE_SHA="الصق هنا SHA رأس main من جدول G5"
bash mc-t31-update.sh
unset GH_TOKEN APPROVED_HEAD_SHA APPROVED_BASE_SHA
```

السكربت يقرأ الحي لحظة التنفيذ بلا توكن، يقارنه بالموافق عليه، ويفشل عند أي اختلاف، ثم يمرر القيمة **الحية** كـ`expected_head_sha`. الصق لي المخرجات (`SC4` وقراءة `mergeStateStatus`).
**إن قررت عدم الدمج بعد T3.1:** لا شيء إضافي يُنفَّذ — PR مفتوح بفرعه المحدث وmain سليمة. هذا هو «التراجع قبل الدمج» الصحيح: التوقف والحفظ — لا الإغلاق ولا حذف الفرع.

**T3.2 — الدمج (موافقة مستقلة ثانية):** أولاً الفحص المسبق **بتوكن G3-R** (لا G3-W) وبعد تعبئة بصمات G4 الثلاث في الجلسة:

```bash
read -rsp "توكن G3-R (لا يظهر): " GH_TOKEN; echo; export GH_TOKEN
export G4_SHA256_SECURITY_MD="بصمة SECURITY.md من G4"
export G4_SHA256_DEPENDABOT_YML="بصمة dependabot.yml من G4"
export G4_SHA256_PR_TEMPLATE_MD="بصمة PULL_REQUEST_TEMPLATE.md من G4"
bash mc-t32-precheck.sh
unset GH_TOKEN G4_SHA256_SECURITY_MD G4_SHA256_DEPENDABOT_YML G4_SHA256_PR_TEMPLATE_MD
```

راجع الشروط اليدوية الثلاثة: (3) سجل G-T1 مكتمل وبصمة ملف التشفير محفوظة · (4) تشغيلات CI للـPR موثقة · (5) أمر التراجع بعد الدمج مدوّن (القالب §تراجع). الصق لي مخرجات الفحص (`CHECKED_HEAD_SHA` · `OLD_MAIN_SHA` · `MERGE_BASE` · `MERGE_STATE_STATUS` · `CI`) ⇒ موافقتك النصية الثانية تسمي صراحةً: **دمج #16 بـsquash + حذف فرع `chore/repo-governance` + كتابة merge SHA + حصيلة CI كما طُبعت (OK أو NO_RUNS) + نتيجة مقارنة القائمة البيضاء** ⇒ ثم الدمج بتوكن G3-W:

```bash
read -rsp "توكن G3-W (لا يظهر): " GH_TOKEN; echo; export GH_TOKEN
export CHECKED_HEAD_SHA="القيمة التي طبعها mc-t32-precheck.sh"
export OLD_MAIN_SHA="القيمة الثانية من مخرجات mc-t32-precheck.sh"
bash mc-t32-merge.sh
unset GH_TOKEN CHECKED_HEAD_SHA OLD_MAIN_SHA
```

`--match-head-commit` يمنع الدمج إن تغيّر الرأس بين الفحص والدمج، والسكربت قبل أمر الدمج يقرأ main الحي ويقارنه بـ`OLD_MAIN_SHA` — فإن تحركت main بعد الموافقة يوقف الدمج **قبل وقوعه** (وتظل بعده نافذة سباق ضيقة لا يجوز إخفاؤها، ويحسمها T4). الصق لي (`STATE` · `MERGE_SHA` · `MAIN_NOW`).

## 9) T4 ثم إغلاق الكتابة ثم T5

**T4 — التحقق بعد التغيير (قراءة فقط، توكن G3-R)** بعد تعبئة `MERGE_SHA` و`OLD_MAIN_SHA` وبصمات G4 في الجلسة:

```bash
read -rsp "توكن G3-R (لا يظهر): " GH_TOKEN; echo; export GH_TOKEN
export MERGE_SHA="من مخرجات الدمج"
export OLD_MAIN_SHA="من مخرجات الفحص المسبق"
export G4_SHA256_SECURITY_MD="بصمة SECURITY.md من G4"
export G4_SHA256_DEPENDABOT_YML="بصمة dependabot.yml من G4"
export G4_SHA256_PR_TEMPLATE_MD="بصمة PULL_REQUEST_TEMPLATE.md من G4"
bash mc-t4-verify.sh
unset GH_TOKEN MERGE_SHA OLD_MAIN_SHA G4_SHA256_SECURITY_MD G4_SHA256_DEPENDABOT_YML G4_SHA256_PR_TEMPLATE_MD
```

**فور نجاح T4 (أو عند أي توقف قبل بلوغه):** ألغِ توكن G3-W من صفحة إدارة التوكنات مباشرة **دون أي طلب API بالتوكن الملغى**، وسجّل في سجل التجربة: اسم التوكن + وقت الإبطال أو الانتهاء + مصدر التأكيد ⇒ **إغلاق G3-W (SC11)** — غياب هذا التوثيق = التجربة غير مغلقة.

**T5 — التقرير:** ترسل لي سجل التجربة المكتمل ⇒ أُعد التقرير المستقل (كل خطوة: الأمر · المعرف · النتيجة · سبب أي فشل · أمر التراجع الجاهز؛ سجل البوابات؛ تأكيد الإبطالين؛ الإعدادات الموثقة؛ خط الأساس قبل/بعد؛ نتيجة القائمة البيضاء؛ الأخطاء المتبقية) ⇒ **التقرير أولًا، والتوقف عند بابك** — قرار التعميم مستقل لك لاحقًا مستودعًا مستودعًا.
